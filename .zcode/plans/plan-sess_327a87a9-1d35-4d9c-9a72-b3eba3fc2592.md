## 目标
让 DEEIX-Chat 支持 Anthropic Agent Skills 标准格式的 skill 包：用户上传 zip（根目录含 SKILL.md + 引用文档/脚本），服务端解压存储，选中技能时注入 SKILL.md + 文件清单，模型通过约定标记**请求式披露**文件内容（后端读取后补充注入）。本次**不做**脚本执行（后续阶段）。

## 现状
- Skill 目前是纯文本：`skills` 表 `markdown` 字段（≤10000 字符），无文件、无 frontmatter 解析
- 注入：`renderSkillPrompts` 将选中技能渲染为 `<skill_context>` XML 块注入 system 消息（`backend/internal/application/conversation/service_skill_prompt.go`）
- 可复用：objectstore 抽象（local/S3，`backend/internal/infra/objectstore`）、docker storage volume 已配置、yaml.v3 已有依赖、MCP 工具链（本次不触碰）、api-contract 从 swagger 自动生成 TS 类型（`pnpm api:generate`）

## 数据模型（`skills` 表新增列，GORM 自动迁移）
- `package_type` VARCHAR(16)：`''`（兼容现有文本技能）/ `package`
- `package_files_json` TEXT：文件清单 `[{path, size, kind}]`（kind: text/binary），SKILL.md 不进清单（由 markdown 列承载）
- `package_root_dir` VARCHAR(255)：zip 顶层目录名（若有，如 `skill-name/`，用于路径映射）
- SKILL.md 内容仍存 `markdown` 列（注入直接用）；其余文件存 objectstore，key = `skills/{scope}/{skillID}/{path}`

## 后端
### 1. zip 解析与校验（新增 `backend/internal/application/skill/package.go`）
- 标准库 `archive/zip`，无需新依赖
- 校验：zip ≤ 10MB、解压后总大小 ≤ 20MB、文件数 ≤ 200、拒绝 `../`/绝对路径/symlink（zip slip 防护）
- SKILL.md 定位：根目录直接存在，或唯一顶层子目录下（剥离顶层目录）；大小写不敏感
- 解析 YAML frontmatter（yaml.v3）：`name` → title/trigger，`description` → description；无 frontmatter 时回退用包目录名/文件名
- 校验 markdown ≤ 10000 字符（沿用现有限制）

### 2. 应用层（`application/skill/service.go` 扩展）
- `PreviewPackage(ctx, userID, zipData)`：解析返回元数据 + 文件清单（不落库）
- `ImportPackage(ctx, userID, zipData)`：解析 → 创建 skill 行（package_type=package）→ 文件逐个 Put 到 objectstore → 更新 package_files_json；失败清理
- `ReplacePackage(ctx, userID, skillID, zipData)`：重新上传覆盖（先删旧文件）
- `GetPackageFile(ctx, userID, skillID, path)`：校验归属/启用（复用 ResolveAvailable 语义）+ path 白名单校验（必须命中清单），返回内容；二进制文件返回不可用错误
- 删除技能时清理 objectstore 文件（`DeleteUser/DeleteBuiltin` 扩展）
- 常量：包大小/文件数/单文件读取上限（如 32KB）

### 3. HTTP（`transport/http/skill/`）
- `POST /api/skills/mine/import/preview`、`POST /api/skills/mine/import`（multipart file）、`POST /api/skills/mine/{id}/package`（重新上传）
- `GET /api/skills/{id}/files/*path`（读取文件内容，文本返回，二进制 415）
- 管理员镜像：`/api/admin/skills/import/preview`、`/api/admin/skills/import`、`/api/admin/skills/{id}/package`（含审计）
- DTO：SkillResponse 加 `packageType`、`files`；SkillSummaryResponse 加 `packageType`；新增预览响应
- swagger 注释 → `pnpm api:generate` 重新生成前端类型

### 4. 注入 + 请求式披露（`application/conversation/service_skill_prompt.go` + 新文件 `service_skill_file_request.go`）
- 渲染：包技能输出 `<files><file path size kind/></files>`；SKILL.md 内容剥离 frontmatter 后注入 `<content>`
- 契约更新：声明"如需查看包内文件内容，在回复中输出 `<read_file path="...">` 标记，系统将提供内容后继续"
- 请求式披露循环（在发送流程中、工具循环之外）：
  1. 模型生成响应 → 正则提取 `<read_file path="...">` 请求
  2. path 必须命中该技能清单（防越权/越界）
  3. 读取文件内容（文本，单文件 32KB 截断、单轮总 64KB 上限）→ 追加一条 `role:"system"` 消息 `<skill_file_content skill_id path>…`
  4. 再次调用模型（无工具）产出最终答案；若仍含请求标记则剥离标记，最多补一轮
- 进程 trace 记录（沿用 skill_context 类型，加 file_read 计数）
